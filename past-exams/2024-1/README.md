# COMP2100/6442 Final Exam | 2024 Semester 1

This repository contains questions for the 2024 S1 Final Exam.

Read and follow the exam specifications carefully to avoid receiving zero marks or losing a certain amount of marks.

You must use
- Java SDK version 17
- JUnit4 (provided in this repository) for testings.

You may follow https://cs.anu.edu.au/docs/student-computing-environment/linuxlabs/keyring/ to 
solve any Keyring issues.

## WARNING!
You must commit and push your work to the exam GitLab server, and ensure your
work is pushed successfully to the server before the end of the exam. We can
only mark what you have pushed. Anything that you forget to push will be 
irretrievably lost. 

You will be marked based on what has been pushed.

You must confirm your submission has been made correctly by checking the commit 
and files on the GitLab web page **within the exam time given**. To re-iterate,
this means pushing your working code continuously, and **much earlier** than the 
exact deadline. Push takes time and networking connections is slower when
it is closed to the deadline, and that is a factor you must consider and manage.

### Instructions
- Do not import non-standard Java libraries.
- Your code must compile successfully to receive any marks.

- The files to be submitted are specified in each question.
  Note that the files should remain in their original locations in the 
  repository (i.e. not moved or renamed), and any other files will not be 
  included or considered during marking.

- A partially correct implementation will usually receive some marks. 
  (i.e., if some test cases **that assess the correctness of the implementation** 
  are provided, passing some tests usually indicate you may obtain some marks).
- There are exceptions, for example in cases where a "dummy" or "Hardcoded" 
  implementation always pass a certain test, there will be no marks if you ONLY 
  pass that particular test. Marking test cases are different from the provided ones
  and marks are not necessarily proportional to the number of tests passed.

- Unless specified otherwise in the questions, you should only create code 
  within designated regions indicated by code comments within the provided  
  files; and do not create new methods or fields.

- In any case, your code must be buildable.

### Recap of Important Notes (From Final Exam Instructions - MANDATORY READING on Ed)
- Commit and push your work regularly as you complete it.
  Remember that we can only mark what is in your exam repository on
  the GitLab server after the exam.

- Do **NOT** wait to the end of the exam to push all your solutions.
  Close to the end of the exam (last 10-15 minutes), the exam server is
  likely to be very busy, and pushing can take much longer than normal.
  *Be prepared for that - don't leave pushing to the last minute!*

- We have provided some basic test cases to you (in the repository) which you can run locally.  
  - Note that your code will be assessed with another set of test cases that are not provided, 
    and the final marks you will get are also not indicated by the tests. 
    It is important that you read and understand the tasks and implement that specification correctly. 
    The tests that are provided are meant to help you get started with code development, 
    but the tests are not the specification definition.  

- Frequently check for announcements on Ed.

- For question-related issues (e.g., suspected a bug in the question), you may 
  contact us using Ed - create private posts.
